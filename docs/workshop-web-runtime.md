# 网页壁纸运行时兼容

Scena 的本地网页播放页和资源通过 `wewall://` 提供。网页始终保留 `allow-scripts` iframe 沙盒，网页设置由按目录隔离的存储兼容层持久保存。

## WebWallGL 本地修补

`wallhaven/Resources/WorkshopPlayer/webwallgl.global.min.js` 保留原有许可，对网页宿主兼容逻辑作两处、场景文字绘制作一处局部修补。更新上游资源时需要复核这些行为并运行对应回归。

1. 同源直载快捷路径只用于 HTTP / HTTPS。自定义协议的入口并未由 HTTP 服务器预先注入 Wallpaper Engine 桥，因此必须走读取 HTML、插入兼容脚本和创建 Blob iframe 的流程。否则 `wallpaperPropertyListener.setPaused` 不会收到通知，音量、帧率与指针兼容代码也会缺失。
2. 已实现 `wallpaperPropertyListener.setPaused` 的网页自行管理媒体和过渡。宿主仍更新兼容层的暂停标记、定时器与帧回调状态，但不额外记录并重播媒体和动画。没有实现该接口的普通网页保留通用暂停 / 恢复兜底。

3. 场景文字层的文字超出文字框时（左对齐的文字从图层原点向右排，右对齐的在原点结束，常会伸出框外），一律扩大文字画布。原先带遮罩特效的图层不扩大、边距固定为 8 像素，判断依据是特效贴图名含 `mask`；条目 `3761179997` 的时钟、日期套用“流动”特效，作者画的流动贴图名为 `psyhue_mask_…`，被误判后文字露在框外的一半被裁掉。扩大画布后，真正的遮罩贴图会随图层拉伸、与文字略有偏差，但文字不再被裁切；文字在框内时与原来完全一致。

第二处规则避免宿主在通知网页恢复后，再次启动网页已取消的旧过渡或旧媒体。它也避免与网页自己的双播放器交接逻辑争用播放状态。

## 视频画面层错位

WebKit 的 `<video>` 画面是单独的原生层。在用户桌面上观察到：网页布局正确（视频元素、底图都是 2560×1440，`videoWidth` 为 1920×1080），但视频层是贴顶、水平居中的 2560×1280 框，16:9 画面被等比放进去，右侧和底部露出底图。2560×1280 正是视频读到尺寸之前的默认比例（300×150）。条目 `3828392144` 在「壁纸直接接收鼠标」模式下点击切换穿搭几乎每次都会出现：页面给正在显示的视频换片源，或把在透明度为 0 的元素里加载的下一段显示出来。

用临时桌面窗口加载该条目、真实点击切换并截取窗口画面逐项排查：偏移 `object-position`、改宽度、加 `transform`、切换 `visibility` / `display`、改 WebView 或窗口尺寸都不能纠正，1.0.36 的 1/32 像素偏移因此无效。只有把视频元素从 DOM 移除再插回原位、重新创建渲染对象，WebKit 才按真实尺寸重建视频层；`insertBefore(video, video.nextSibling)` 插回原位会被 WebKit 当作无操作，必须先移除。

1.0.38 在视频显示状态变化停止 150 毫秒后重建可见的视频，能纠正但会先错位、再闪一下恢复，而且漏掉了部分换片路径和主窗口预览。逐帧截图核对后确认：WebM 的画面层尺寸在解码出第一帧之后才确定，读到元数据时重建太早。1.0.39 改为在每次 `loadeddata`、`playing` 以及宿主恢复可见时重建，又带来两个问题：`playing` 在每次暂停后恢复、循环衔接时都会触发，后台反复暂停恢复和穿搭自动轮播时视频被反复移出插回，播放卡顿，页面的轮播衔接被打断（提前切到下一段、卡一下又切回）；正在显示的视频直接换片源时，新片源的头几帧仍画在旧框里，随后跳成全屏，看起来像缩放。

现在的做法：每个视频的每个片源只在解码出第一帧（`loadeddata`）和第一次开始播放（`playing`）时各移除再插回一次，暂停后恢复、循环衔接、宿主恢复可见都不重建；换片的页面这时通常还没把它显示出来，看不出变化。正在显示的视频换片源时（拦截 `src` 属性、`setAttribute('src')`、`load()`，并以 `loadstart` 兜底）临时设为 `visibility: hidden`，解码出第一帧并重建后立即恢复（最长 3 秒兜底）。新片源没有画面前视频元素本来就是透明的，所以不会比页面原本多露出底下的内容；1.0.40 等到开始播放才恢复，多露出了封面。曾尝试用画布 `drawImage` 定格旧画面、逐帧照着新视频画，但 WebKit 取视频帧要同步等待 GPU 进程（`waitForVideoOutputMediaDataWillChange`），视频没出帧时会一直等，完整测试中冻住了同一网页进程里的所有页面，已放弃。透明度为 0 的视频不处理。视频元素尺寸真的变化（`ResizeObserver`，含窗口缩放）或宿主刷新视口时，等变化停止 200 毫秒后重建可见的视频。播放中的视频随即继续播放（同步插回本身不会暂停），Web Animations 淡入动画不受影响（CSS 过渡会被取消，所以只在上述时机重建）；不修改下载的网页文件。

1.0.42 之后在实际 App 中又出现错位。系统日志（`PlaybackSessionManagerProxy::createLayerWithID`）显示，第一帧时的重建有时在页面布局按真实尺寸更新之前完成，WebKit 按默认的 2:1 框（2560×1280）创建画面层，约 0.35 秒后 `setVideoLayerFrame` 才把外框改成 2560×1440，但画面留在贴顶的旧框里；实际 App 中约三分之二的换片出现这种建层，临时测试窗口中约七分之一，且测试中未能复现可见错位。因此在两次重建之后各补一次延迟重建：第一帧后 0.5 秒（片源未变时），开始播放后 1 秒（只针对仍在显示且在播放的视频）。全屏临时窗口每秒截图 150 帧均正常，穿搭片段都正常播完。

验证用临时桌面窗口加载条目 `3828392144`，以原生鼠标事件点击切换穿搭，高频截取窗口画面（约每 0.1 秒），用错位框右边界（x≈2417）两侧的像素差判断：关闭修复时每次切换差值约 97～218（正常画面 2～4）；1.0.39 的做法在直接换片源的路径上有约 0.4 秒错位帧；现在 3 次切换的 69 帧均正常。模拟后台暂停恢复 6 次，重建次数从 12 次降到 1 次（当前片源尚未做过的那次）。关闭修复对照可见，切换开头停在特写、约 0.4 秒后硬切到入场视频全景是壁纸本身的过渡（页面先暂停旧视频，换片源时瞬间盖上幕布，新视频开始播放后幕布在约 0.5 秒内淡出）。`WorkshopVideoLayerRefreshTests` 覆盖第一帧和开始播放时重建（含隐藏的视频）、暂停恢复不重建、换片源期间画布盖住、视频隐藏，恢复后画布撤掉、窗口缩放只重建可见的视频、元素位置和作者样式不变、播放不中断。



- `WorkshopWebRuntimeTests` 验证自定义协议入口实际获得 `__weSetPaused`，标准暂停消息送达，网页取消的旧动画不会在恢复后重新播放。
- `WorkshopMediaResumeTests` 用临时生成的六秒视频，在中途播放后进入 / 退出交互并暂停 / 恢复，核对暂停时刻、恢复位置、网页实例及视频和底图的布局。分别覆盖网页自行管理播放和通用兜底两种情况。

上述回归不等同于所有第三方网页或所有桌面切换场景验收。真实壁纸需继续检查中途切换应用、自动换片、显示器与 Spaces 变化下的画面和播放连续性。

本轮另在可见的临时桌面窗口中加载本机条目 `3828392144`，在六秒处退出交互并恢复播放：同一视频继续到约 7.85 秒，视口和视频元素均保持 2560×1440；通过原生窗口截图观察，未出现原先的缩小视频叠在底图上、底栏与画面错位现象。测试使用独立的临时设置，未修改下载文件；真实用户环境的长时间播放仍需继续验收。

最终完整单元测试 190 项通过；Apple 芯片 / Intel 通用构建与签名校验通过，最低系统版本保持 macOS 14.0。
