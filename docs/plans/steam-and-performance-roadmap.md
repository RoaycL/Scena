# Steam 与本地壁纸性能优化方案

核查日期：2026-10-16。代码基线：`88e78ed`（1.0.26）。

本文是根据当前源码和上游项目核验后的设计方案。没有读取 WaifuX 的源码或认证凭据；用户提供的符号、日志与目录描述视为调研线索，不能据此确认它的完整实现、令牌寿命或功耗。

## 执行进度

- 第一阶段已实现：列表 480 / 海报 1920 像素的视频封面、全局双路生成、共享任务、前台请求优先、导入/下载后预热、256 MiB / 14 天磁盘缓存及设置页清理。
- 工坊索引已接入启动快照、文件属性增量核验、原子持久化、离线保留和下载后的主动失效；播放和桌面海报准备不再递归统计文件大小。
- 场景/网页预览与旋转指示器已接入窗口遮挡、隐藏及最小化处理，保留首帧准备和手动暂停意图。
- 本轮没有接入文件系统事件流。嵌套资源的目录大小会在已知下载事件主动失效，或上次完整核验超过 24 小时后的下一次扫描时重新计算；入口、project 和已有预览文件则每次扫描核验。
- 第二阶段已实现：SteamKit2 认证 helper、手机扫码、macOS 登录钥匙串持久凭据、启动静默恢复、社区会话按需续签；保留网页登录兼容入口及现有 SteamCMD 下载方式。详见 [认证组件说明](../steam-authentication.md)。
- 原生 CDN 下载、代理切换和场景烘焙仍是后续阶段。
- 验证使用临时素材与自动化用例；尚未完成用户真实资料库的性能测量及交互验收。
- 验证结果：79 项单元测试全部通过（含真实 4K 视频取帧及透明窗口显示/隐藏通知）；Release 的 arm64/x86_64 双架构编译、签名检查通过。测试主机为 macOS 27.0.1，尚未在 macOS 14 实机验收。本轮未更改版本号、提交或发布。
- 第二阶段验证：100 项测试通过（含参数化实际运行 102 次），Release 双架构与完整签名检查通过。用户在独立预览版扫码后同步 78 个订阅；完全退出后重启，无需再次扫码并重新同步成功。尚未执行真实账号的订阅写操作、服务端撤销和 macOS 14 实机验证，未提交或发布。

## 必须纠正的假设

1. **OpenID 不是 Steam 客户端认证替代品。** Valve 文档说明它用于验证并获取 SteamID，不能用它获取工坊下载会话。认证应采用 SteamKit 的 QR / credentials 流程。[Valve 身份认证文档](https://partner.steamgames.com/doc/features/auth)
2. **RefreshToken 不等于永久登录。** 需要处理过期、撤销、平台类型、网络离线和令牌轮换。SteamKit 示例明确展示用 refresh token 登录以及更新社区 access token；轮换时必须保存新令牌。不要承诺固定“数年有效”。[SteamKit 社区 Cookie 范例](https://github.com/SteamRE/SteamKit/blob/master/Samples/002_WebCookie/Program.cs)
3. **网页 Cookie 不能无条件通过任意 refresh token 换得。** SteamClient 类型可能需要已认证的 CM 连接，不能假设所有场景都能用独立 HTTP 请求完成。[认证库维护者文档](https://github.com/DoctorMcKay/node-steam-session#refreshaccesstoken)
4. **注入代理环境变量不保证所有网络都走代理。** Web 请求、CM TCP/WebSocket、CDN HTTP 的传输栈不同；HTTP、SOCKS、PAC、自动发现也不是同一种配置。必须逐条验证，不能承诺解决所有地区连接问题。
5. **元数据不能仅靠超长 TTL 保证正确。** 外部文件更新、迁移、删除和磁盘离线都需要区分，不能永久返回陈旧索引。
6. **烘焙会改变体验。** 鼠标交互、音频响应、时间变化与用户自定义参数可能无法保留；原生视频解码和显示合成仍有开销，不能保证 GPU 为零或 CPU 小于 1%。
7. **WallpaperExtensionKit 不是可直接依赖的公开 macOS 14+ 能力。** 本机 Xcode SDK 将其列在 `System/Library/PrivateFrameworks`。不纳入当前稳定版的锁屏承诺。

## 第一阶段：补齐缓存与后台运行

### 1. 多规格视频封面

统一 `GalleryItem.thumbnailSource`、`ImmersiveBackground.videoPoster` 与 `PlaylistsView.thumbnailSource` 中的视频取帧入口。

- 增加列表封面与背景海报两个规格，初始候选长边分别为 480 和 1920 像素，后续按屏幕与测量结果调整。
- 在 `AVAssetImageGenerator` 设置 `maximumSize` 后取帧，而不是只对取出的整帧使用 DownsamplingImageProcessor。目前依赖中的 `AVAssetImageDataProvider(assetURL:seconds:)` 没有设置这个上限。[Apple 取帧尺寸文档](https://developer.apple.com/documentation/avfoundation/avassetimagegenerator/maximumsize)
- 缓存键包含规范化文件地址、文件修改时间、大小、规格、取帧策略版本；同路径替换视频后不能继续显示旧封面。
- 共用进行中的生成任务，限制后台并发；可见卡片优先，后台预生成可取消。一个消费者取消不能破坏其他可见消费者。
- 下载、导入结束时生成列表封面；旧资料库按需补齐，不在启动时无界并发预热全部视频。
- 保留原图和原视频；封面属于可重建缓存，并纳入容量上限及清理入口。

验收：4K/8K 输入生成的列表封面像素不超过约定尺寸；相同视频多处出现只生成一次；列表/海报缓存分离；替换文件失效；生成取消后可见条目仍能重新加载。用同一批视频比较冷缓存峰值内存与滚动表现。

### 2. 工坊增量元数据索引

增加独立的后台索引存储，先恢复有效快照，再增量核验。第一版可使用原子写入的版本化 JSON 快照，不必立即引入数据库。

- 按根目录与相对路径记录条目，保存解析结果、project 文件指纹、入口/预览文件信息、目录大小及其校验状态。
- 未变化的 project 不重复解析；大小计算从发现列表的关键路径移出，下载/导入时更新，并在后台按需核验。
- 仅检查根目录修改时间不足以发现嵌套文件变更；结合已知写入事件、文件变更通知与周期性核验。
- 根目录离线时保留记录并标记不可用，不能当成文件删除执行 GC；重新挂载后重新核验。
- 完整且成功的扫描才清理已删除项；扫描失败、被取消和旧批次返回均不能覆盖当前索引。
- 索引损坏可重建；迁移路径沿用当前存储迁移与播放列表引用更新机制。
- 缓存快照不直接作为“文件已下载完整”的依据。订阅差集、任务完成和设为壁纸之前仍需检查文件与下载收据。

验收：第二次启动未变条目不重读 project、不逐条递归统计大小；外部修改、单项删除、根目录迁移、磁盘拔插和损坏索引均能恢复正确列表；不会重复排队已有完整壁纸。

### 3. 页面可见性与动效

- 复用原生 `NSWindow` 遮挡通知与现有自动暂停逻辑，避免另建高频轮询追踪器。
- 视频预览保留已有遮挡暂停；为 `WorkshopPlayerNSView` 的 App 内预览补充同等行为，桌面播放器继续由 `LiveWallpaperController` 管理。
- 切换页面、最小化、隐藏、完全遮挡时，暂停无意义的旋转与预览渲染；恢复后按用户的播放意图恢复。
- 首帧准备和实际播放区分处理，避免透明等待中的视图被暂停，导致永远拿不到首帧。
- 核查 `DownloadingRing` 与同步旋转，目前未发现大量自定义 Shimmer，因此不以“注销所有骨架屏”作为虚构改动目标。
- 保留现有 `WallpaperWindowLifecycle` 对 active/retiring 资源与过期回调的管理，避免预览或烘焙接入重新引入残留窗口。

验收：相同壁纸下比较主窗口可见、遮挡、最小化、切页后的 CPU/渲染活动；检查首帧正常出现、手动暂停不被自动恢复、其他屏幕桌面仍正确播放。未测量前不写节电百分比。

## 第二阶段：统一 Steam 登录

首选验证 **Swift 界面 + 自有 .NET/SteamKit2 helper**。不复制 WaifuX 二进制，也不从零用 Swift 重写 Steam 协议。Swift 保留 Keychain 与用户界面，helper 负责 CM、认证和社区会话生成。

SteamKit 上游已有二维码挑战、二维码更新、轮询结果与 refresh token 登录范例。[QR 范例](https://github.com/SteamRE/SteamKit/blob/master/Samples/001_AuthenticationWithQrCode/Program.cs)

### 服务边界

- 通过私有 stdin/stdout 传递版本化 JSON 消息，带请求 ID、取消与事件类型；stderr 日志脱敏。避免启动对局域网开放的 HTTP 服务。
- helper 按需启动、空闲退出，崩溃后有限次重启并保留待恢复的任务意图。
- refresh token 交由主应用保存在 Keychain，不放进命令行、UserDefaults、下载目录或普通日志。用户名、账号显示信息可以单独保存。
- 初版优先扫码，保留网页登录兼容入口；账密与验证码作为后续独立交互，不伪装成人机验证永远不会出现。
- 二维码过期/更新、轮询间隔、用户取消、授权拒绝均有明确状态；关闭登录页就取消对应会话。
- 启动时尝试恢复，刷新单飞合并；刷新后的凭据原子替换。离线与服务器故障不直接清除凭据，明确失效才要求重新授权。
- 为 helper 配置独立 LoginID，测试与 Steam 桌面客户端同时在线，避免会话互踢。
- 支持 arm64/x86_64、macOS 14 起，评估 self-contained 包体与启动开销；发布包校验 helper 签名与协议版本。
- 依赖授权与通知文件随具体打包方案核对。[SteamKit 许可](https://github.com/SteamRE/SteamKit/blob/master/LICENSE)

### 先做纵向验证，再切换默认登录

用用户自己的授权测试账号走通：扫码 → Keychain 保存 → 完全退出 → 重启静默恢复 → 获取社区会话 → 读取订阅 → 手动订阅/退订 → 撤销授权后重新扫码。

验证时不输出令牌。登录成功不代表拥有 Wallpaper Engine，也不代表受限条目一定可下载。

## 第三阶段：CDN 下载与网络适配

### 下载后端

在持久任务队列下抽象统一后端，SteamCMD 与新 helper 使用相同条目 ID、状态和完成收据，避免重写已有的暂停、停止、恢复、重试语义。

- helper 接收条目、目标目录及恢复检查点，输出结构化字节进度与逐项结果。
- 先验证单个工坊 PublishedFileID 到 UGC/manifest/CDN 的完整下载链路，再扩大到批量。
- 分片并发设全局上限，避免“任务并发 × 分片并发”放大网络与磁盘压力；速度、重试与服务器切换需有上限。
- 验证文件块和最终文件，再原子完成并写收据；中断时保留可校验块，不能把半成品标为已完成。
- 暂停写检查点；停止清理任务意图但不删除用户已有壁纸；重启后按当前策略保持暂停，由用户恢复。
- 过渡期保留 SteamCMD 后端。未经账号与异常场景验证，不移除现有可用下载方式。

DepotDownloader 是同一生态中可核对的工坊下载、分片并发与 QR 参考实现；它使用 GPL-2.0，不能将其中实现当作可随意复制的片段。[上游文档及许可](https://github.com/SteamRE/DepotDownloader)

验收包含：视频/场景/网页条目、无权限、删除条目、断网、进程崩溃、暂停恢复、磁盘满、外接盘拔出、路径迁移和校验失败。需比对原文件一致性及每个请求 ID 的明确结果。

### 网络适配

- 用 `SCDynamicStore` 监听相关系统代理配置；在服务启动时传入可用快照，并去重、防抖。[Apple 文档](https://developer.apple.com/documentation/systemconfiguration/scdynamicstore)
- 区分系统代理与继承的环境代理，定义优先级；PAC/SOCKS 不简单映射成 HTTP_PROXY。
- 原生 URLSession、CM、CDN 分别做直连和代理连通性检查，错误信息区分 DNS、连接、认证与权限失败。
- 代理变更不要直接杀死正在下载的 helper：先安全暂停、保留检查点，再重连或重启并恢复任务。
- 代理口令和完整含凭据的 URL 不写日志。

## 后续实验：场景烘焙

只提供用户主动开启的“节能视频副本”，保留实时场景原文件与返回入口，不默认把所有场景转换为 MP4。

- 先验证当前 webwallgl 对场景的兼容性、稳定帧时间与确定性捕获；无法正确渲染的场景不能靠烘焙修复。
- MVP 允许手动循环时长，不承诺对随机粒子、音频响应和非周期场景自动找到无缝循环点。
- 转换任务包含分辨率、帧率、编码参数、进度、取消、磁盘空间及断电失败清理。
- 烘焙缓存键包含场景内容、渲染器版本与用户参数；源文件或配置变化时失效。
- 控制后台资源，优先接电与用户空闲时转换；避免播放、下载和烘焙同时争用资源。
- 先对一组固定场景比较实时渲染与编码副本的功耗、画质、空间和循环接缝，再决定是否扩大范围。

## 建议执行顺序

1. 先做视频封面与工坊增量索引，补齐预览可见性管理；这是当前代码可直接验证的性能缺口。
2. 同时把 SteamKit 认证作为独立纵向验证，完成扫码、持久化、静默恢复和社区操作。
3. 认证链路稳定后接 CDN 后端及代理热切换，保留旧后端用于过渡。
4. 场景烘焙独立立项，锁屏私有框架暂不进入稳定版。

每阶段独立验证与发布，不把认证、下载、索引和渲染器同时替换。具体性能提升以相同素材与相同设备的前后测量为准。
