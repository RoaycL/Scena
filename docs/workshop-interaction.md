# 网页壁纸交互与播放方式

## 操作

已下载且项目类型为 `web` 的工坊壁纸可进入交互模式。入口在详情手形按钮、右键菜单、顶部 LIVE 菜单、系统「动态壁纸」菜单以及菜单栏图标菜单；系统菜单快捷键为 Command–Shift–I。

交互时临时将当前桌面壁纸窗口放到普通窗口层，交给原生 WKWebView 接收点击、按下 / 抬起、拖拽、滚轮和键盘。右上角显示退出提示。按 Esc 或点「退出交互」后释放键盘焦点，将窗口放回桌面层并恢复鼠标穿透；保持同一个网页实例，已选择的当前播放方式不会因退出交互而被重新加载。

切到其他 App、切换壁纸、停止壁纸、显示器配置变化或系统休眠时退出交互；交互期间不让播放列表自动切换壁纸。退出时重新同步整个屏幕的窗口与网页视口，网页可见性由原生暂停策略控制，避免仅因 App 失焦被挂起。网页本身的默认定格、循环及其他选项仍遵循作者实现。

网页继续使用 `allow-scripts` 沙盒。遇到沙盒禁止浏览器存储的页面时，宿主提供按本地壁纸目录隔离的 `localStorage` 兼容层，并持久保存设置；`sessionStorage` 仅在本次页面内有效。每项最多 512 个键、总计 256 KiB。不会修改下载的网页脚本。Windows 专用接口、额外浏览器权限及作者自行实现的交互仍可能需要单独适配，不能保证所有工坊网页完全兼容。

本地网页入口需要完整注入 Wallpaper Engine 兼容桥，实际传递标准暂停 / 恢复通知。已提供播放管理接口的网页自行控制媒体交接和动画，宿主不会额外重播已取消的过渡。实现与测试见[网页运行时兼容说明](workshop-web-runtime.md)。

桌面窗口单独向 WebKit 报告渲染可见，避免 Finder 桌面层的遮挡判断冻结 CSS 动画和视频合成；不是仅修改网页的 `document.hidden`。[WebKit 的窗口可见性判断](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/mac/PageClientImplMac.mm#L196-L216)同时读取 `isVisible` 和 `occlusionState`。系统真实遮挡状态仍单独保留，Scena 使用真实状态和覆盖窗口判断省电暂停，手动暂停、全屏与系统休眠策略继续生效。

## 转换开关

「下载后自动转为视频」关闭时：

- 桌面、工坊详情和大图预览（含播放列表预览）都使用源文件。
- 正在播放转换视频的桌面重新加载源文件；已有转换视频不删除。
- 自动转换停止，等待队列保留；即使手动生成视频，也不会在开关关闭时选用它播放。
- 原生视频壁纸始终播放原始视频，不受此开关影响。

开启后允许使用仍有效的转换视频。显式进入网页交互会回到源网页，并在退出交互后保留当前网页实例；重新应用壁纸时按开关选择播放方式。

## 验证范围

完整单元测试 190 项通过；Apple 芯片与 Intel 的通用 Release 构建及签名校验通过，最低系统要求保持 macOS 14.0。回归用例覆盖关闭开关不读取转换缓存、原生视频不受开关影响、桌面窗口输入与键盘焦点的进入 / 恢复、网页视图 hitTest、停止后不能重新启用输入，以及场景壁纸不误用网页交互。新增真实 WKWebView 沙盒回归，覆盖直接访问 localStorage 的启动脚本、按钮响应、设置持久保存与隔离、配额、交互切换后的全屏视口，以及暂停 / 恢复可见性。

另在隔离测试窗口中加载本机条目 `3818955880`、`3828392144`、`3810650535`：三个条目均完成初始化，播放方式按钮响应，选择单项循环后视频播放，交互切换后窗口和网页保持 2560×1440，暂停 / 恢复后视频继续，未记录到网页运行错误。测试未修改下载文件或网页内部脚本。实际桌面的长时间播放、多屏、Spaces 切换与完整鼠标操作仍需新版验收。

追加换片中途退出交互、暂停再恢复的测试：每个条目连续选择三段视频，九次换片的静态图与视频元素均保持 2560×1440，视频继续推进。修复前 `3810650535` 的揭幕 CSS 过渡停住，视频保持在零秒；修复桌面窗口的 WebKit 可见性后，同样测试三个条目全部通过。永久回归用例保留桌面层 CSS 遮罩过渡完成检查；真实屏幕上的合成残影还需运行安装后的新版确认。
